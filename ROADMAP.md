## LampArray (11.10.2026)

Стандарт HID LampArray (страница 0x59) — подсветка «Динамического освещения» Windows: устройство само сообщает число ламп, их место, назначение и клавиши. Принято: свой драйвер устройства в приоритете, LampArray — для устройств без своего драйвера и как источник дополнительных зон.

- [x] Чтение LampArray по описанию отчётов (номера отчётов не зашиты), сведения в `--diagnose`, тест `rgbtray --lamparray-test <файл> <rrggbb> <секунды>`.
- [x] ASUS (0B05:19B6): 8 ламп — 4 зоны клавиатуры (слева направо) и 4 акцентные лампы по углам нижнего края корпуса; проверено на железе (11.10.2026): все шаги теста видны; 4 лампы корпуса горят каждая своим цветом (яркость у них разная). Первая команда сразу после взятия управления теряется — после `AutonomousMode = 0` нужна пауза (~1 с).
- [x] Подсказка «Включено динамическое освещение Windows» (v0.6.2) (`HKCU\Software\Microsoft\Lighting\AmbientLightingEnabled`, также по устройствам в `Devices\*`) с кнопкой «Открыть параметры» (`ms-settings:personalization-lighting`).
- [x] Универсальный драйвер LampArray для устройств без своего драйвера (v0.6.3): статичный цвет, выкл., яркость; дыхание и спектр — анимацией из приложения (~30 кадров/с); имя карточки из названия устройства. Виртуальные устройства служб производителей (`HID_DEVICE_SYSTEM_VHF`) пропускаются. Проверен на ASUS через `RGBTRAY_LAMPARRAY_ALL=1` (11.10.2026).
- [x] Цвета клавиш для LampArray-клавиатур (v0.6.6): кнопка «Клавиши» у LampArray-устройств с лампами, привязанными к клавишам; коды редактора → HID usage → лампы по InputBinding; отправка пачками через LampMultiUpdate (поля ячеек — массивом или по одному, как у ASUS). Мульти-обновление проверено на ASUS (8 ламп разными цветами одним отчётом, 11.10.2026); редактор G915 через общий путь работает как раньше; само сопоставление клавиш не проверено — нет такой клавиатуры.
- [x] ASUS (v0.6.3): одна карточка; один цвет, спектр, выкл. — через Aura; зоны через LampArray: 1–4 (клавиатура слева направо) и ↖ ↗ ↙ ↘ (лампы корпуса). Зоны любых LampArray-устройств строятся из описания ламп: клавиши без привязки — по одной, остальное по назначению; группы из 2–4 ламп делятся по положению. Проверено на железе (11.10.2026).

## Этап 2. Устройства как дополнения

Как пользователи добавляют свои устройства, от простого к сложному:
1. Ничего не делать: устройство со стандартом LampArray работает через универсальный драйвер.
2. «Запросить поддержку устройства…» в меню: отчёт + форма на GitHub (v0.6.1); устройство добавляем мы, пользователь проверяет тестовые сборки.
3. Файл профиля в `%APPDATA%\rgbtray\devices\*.toml` для известного протокола (Razer, QMK/VIA, Logitech HID++, ASUS Aura): без компиляции; удачные профили входят во встроенный список.
4. Свой драйвер на Rust для нового протокола: шаблон, CONTRIBUTING, PR, проверка CI.
5. Закрытый протокол: инструкция, как записать обмен фирменной программы с устройством (Wireshark + USBPcap) и приложить к запросу.
6. Позже, по спросу: скриптовые плагины.

Порядок: универсальный LampArray → общий драйвер QMK/VIA и профили Razer → документация для разработчиков.

G915 — период эффекта; LampArray и QMK — анимация приложения (смена скорости без скачка); ASUS Aura — 3 ступени (0xE1/0xEB/0xF5, как в asusctl); MacroPad — скорость эффекта VIA. У Razer в протоколе скорости нет. Проверено на железе (11.10.2026): G915, ASUS и MacroPad реагируют на ползунок, но каждое со своей скоростью (у ASUS 3 ступени, у прошивок свои шкалы).
- [x] Скорость для каждого устройства (v0.6.11), как яркость: при выбранной карточке ползунок — «Скорость устройства», сдвиг от общей (середина — как общая, к ней ползунок примагничивается); множители складываются (общая ×2 и своя ×2 = ×4, предел — от ¼ до 4×). В карточке значок скорости и множитель (например, «×2»), пока устройство дышит или переливается. Хранится в пресетах. Анимации приложения идут каждая в своём времени; устройства с одинаковой скоростью дышат в такт. Проверить на железе: выровнять скорости G915, ASUS и MacroPad.
